2. Objetivo do Projeto

Desenvolver e disponibilizar uma API RESTful modular para o gerenciamento de catálogo e controle de estoque de uma livraria local em expansão. O sistema fornecerá aos operadores e administradores uma interface de serviços padronizada, rápida e consistente para o cadastro, consulta, atualização e remoção de livros e categorias literárias.

3. Justificativa

A livraria local identificou a necessidade urgente de modernizar seus controles e expandir suas operações comerciais. Atualmente, o controle descentralizado e informal gera inconsistências de estoque, dificuldade na localização de títulos e lentidão no atendimento aos clientes.

A construção de uma API desacoplada com arquitetura em camadas (MVC) resolve o problema imediato de organização de catálogo e gestão de estoque, ao mesmo tempo em que prepara a empresa tecnologicamente para futuras integrações (como sistemas web de frente de loja, aplicações móveis ou novos canais de vendas), reduzindo retrabalho e custos operacionais futuros.

4. Escopo Incluído (O que o projeto vai entregar)

✔ Funcionalidades e Entregas Contempladas
  • Módulo de Livros (CRUD Completo): Rotas para cadastrar, listar todos, buscar por índice/ID, atualizar dados e remover livros do catálogo;
  • Módulo de Categorias (CRUD Completo): Cadastro e manutenção de categorias literárias e associação direta com os títulos;
  • Controle de Estoque: Registro e atualização da quantidade de unidades físicas disponíveis por exemplar cadastrado;
  • Autenticação Básica: Proteção e controle de acesso para operações sensíveis e administrativas (criação, edição e exclusão de itens);
  • Arquitetura MVC: Separação limpa em camadas (routes/, controllers/, services/, models/);
  • Padronização REST e HTTP: Retorno coerente de cabeçalhos e códigos de status (200 OK, 201 Created, 400 Bad Request, 404 Not Found, 500 Internal Error);
  • Qualidade e Documentação: Adoção de boas práticas de Clean Code, diagrama UML de classes e instruções completas de execução no README.md.

5. Escopo Excluído (O que NÃO será entregue nesta versão)

✖ Fora de Escopo / Versões Futuras
  • Gateway e Pagamento Online: Não haverá integração com processadoras de cartão de crédito, Pix, boletos ou carteiras digitais (ex.: Stripe, Mercado Pago);
  • Aplicativo Mobile: Não faz parte desta entrega o desenvolvimento de apps nativos para Android ou iOS;
  • Inteligência Artificial e Recomendações: Algoritmos de sugestão inteligente de leitura por perfil de usuário ficam para etapas posteriores;
  • Sistema de Avaliações e Resenhas: Comentários públicos e notas deixados por leitores/clientes finais;
  • Interface Gráfica para o Consumidor Final (E-commerce B2C): O produto desta etapa é estritamente o serviço de back-end (API REST);
  • Cálculo Automatizado de Frete: Não haverá integração externa com Correios ou transportadoras.

6. Premissas

  • Stack de Desenvolvimento: A aplicação é desenvolvida na plataforma Node.js com o framework Express em JavaScript;
  • Evolução da Camada de Dados: O armazenamento provisório em memória nos services será progressivamente migrado para persistência estruturada/banco de dados;
  • Integração de Disciplinas: A equipe atua conjuntamente no desenvolvimento técnico (Back-End) e no planejamento/gestão (PSOF);
  • Controle de Versão: O repositório central no GitHub é a fonte oficial de integridade de código e documentação.

  • Equipe Fixa: Composta estritamente pelos 4 integrantes formalmente designados no Grupo 4;
  • Orçamento Financeiro Zero: O projeto dispõe de R$ 0,00 de orçamento, exigindo uso exclusivo de tecnologias e ferramentas de código aberto e gratuitas;
  • Padrão Tecnológico: Adoção obrigatória do padrão RESTful e arquitetura MVC sob as diretrizes pedagógicas do SENAI.

8. Critérios de Aceitação

1. Funcionalidade REST Completa: Todas as rotas de Livros e Categorias operando conforme especificação (CRUD executável via requisições HTTP).
2. Robustez e Tratamento de Erros: Retorno exato de status 200/201 para requisições bem-sucedidas, 404 para itens inexistentes e 400 para payloads mal formatados.
3. Aderência Arquitetural: Separação nítida de responsabilidades entre rotas, controladores, serviços de negócio e modelos de domínio.
4. Reprodutibilidade Técnica: O projeto pode ser baixado, instalado via npm install e iniciado via npm run dev sem erros em qualquer ambiente homologado.
5. Defensabilidade Oral: O grupo ser capaz de justificar com clareza e solidez todas as decisões registradas neste documento perante a banca na SA1.
